01 / PROJECT OPS CORE

项目部不是“催进度”。
我们负责让项目持续移动。

一个团队可以有技术、有故事、有目标，但只要节点模糊、反馈失联、版本混乱、任务无人负责，项目就会停在原地。项目部的任务，是持续回答四个问题：现在在哪里？卡在哪里？谁能推动？下一步是什么？

MAP / SCAN

看清项目

团队、技术、阶段、目标赛事、材料版本、最近节点和关键风险，先建立完整地图。

TRACK / QUEST

跟住节点

把“最近要改”转成 OWNER、DEADLINE、STATUS 和可验证结果。

CONNECT / LINK

连接反馈

让团队、评委、老师与工作室之间的信息准确流动，而不是层层失真。

REVIEW / LOOP

推动迭代

记录反复出现的问题，判断项目是否真的因为反馈发生变化。

06 / BOSS RISK REGISTER

每个项目都会遇到 Boss。
先看见它，才有机会击破它。

BOSS R01

只剩 PPT

表达跑在技术与证据前面。画面越来越漂亮，项目本身却没有增长。

BOSS R02

无人负责

所有人都知道要改，却没有任何人真正拥有任务。

BOSS R03

反馈堆积

专家说了很多，但没有被翻译成下一步行动。

BOSS R04

信息断层

老师的意见没有传到真正执行的人，信息在转述中不断损耗。

BOSS R05

版本失控

final、final2、final真的最终版同时存在。

BOSS R06

赛后停止

竞赛获得的反馈没有继续进入研发、产品或下一赛事。

11 / JOIN THE PARTY

PLAYER
READY?

不要求你自带项目，也不要求懂所有技术。我们更在意：你是否对“一个想法怎样真正往前走”感兴趣，能否持续跟进，并对下一步保持敏感。

适合加入项目部的玩家

  • 看到模糊任务，会想追问“具体下一步是什么”。
  • 愿意和不同专业、不同角色的人沟通。
  • 不怕长期项目，也不只追求短期结果。
  • 能记录、整理并持续追踪反馈。
  • 对科创竞赛、真实项目和团队成长感兴趣。

你不需要提前解锁

不需要自己已经有创业项目，不需要精通所有技术，也不需要一开始就会项目管理。你可以从看懂项目摘要、整理一次反馈、维护一个节点开始，逐步建立对技术、用户、竞赛、团队与表达之间关系的理解。
